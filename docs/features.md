# 機能設計

## 1. 機能一覧
| # | 機能 | 画面 |
| --- | --- | --- |
| F1 | 指標の表示 (○/×) | `/` |
| F2 | 指標の解説ポップアップ | `/` |
| F3 | ルーレットを回す | `/` |
| F4 | 指標の自動取得 (Cron) | - |
| F5 | 履歴の表示 | `/history` |
| F6 | エラー時の表示 | 全 URL |

## 2. ルーレット画面の仕様 (F1〜F3)

### 2.1 指標の表示 (F1)
- 6 つの指標を、それぞれ ○/× で表示する。ユーザーは ○/× を変更できない (F4 の自動判定の結果を表示する)。
- 指標の値を取得した日時を併記する。

### 2.2 指標 (6 種類)
| id | 名称 | ○の条件 |
| --- | --- | --- |
| cpi | 物価 | 消費者物価指数が前年比+2%超 |
| wage | 実質賃金 | 前年比でプラス |
| shunto | 春闘 | 賃上げ率が物価上昇率を上回る |
| mood | 消費者態度指数 | 前年より改善 |
| stock | 日経平均 | 年間でプラス |
| bonus | 冬のボーナス | 前年より増加 |

### 2.3 指標の解説ポップアップ (F2)
- 指標をタップすると、モーダルで「指標の意味」「○の条件」「出典 (取得元)」を表示する。
- 別ページにはしない (スマホでの見やすさを優先)。

### 2.4 ルーレットの仕様
**盤面**
- 盤面は 10 マスで、1 マスの角度は 36 度。真上の指針から時計回りに 0 番〜9 番とする。
- 各マスは「ハズレ」「当たり」「大当たり」のいずれか。

**当たり枠の数**
- 当たり枠数 = `min(1 + ○の指標数, 6)`。指標がすべて × でも当たり枠は 1 つ (お年玉が減ることはない)。上限は 6。

**当たりの配置**
- 当たり枠は盤面に偏らないよう均等に散らす。k 番目 (k = 0, 1, …) の当たりは `floor(k × 10 ÷ 当たり枠数)` 番のマスに置く。
- 当たり枠が 4 以上のとき、0 番目の当たり (0 番マス) だけを大当たりにする。

| 当たり枠 | 当たり・大当たりのマス |
| --- | --- |
| 1 | 0 |
| 2 | 0, 5 |
| 3 | 0, 3, 6 |
| 4 | 0 (大), 2, 5, 7 |
| 5 | 0 (大), 2, 4, 6, 8 |
| 6 | 0 (大), 1, 3, 5, 6, 8 |

**上乗せ額**
- ハズレ +0円、当たり +500円、大当たり +1,000円。
- 基準額 (年齢ごとの金額など) は本システムでは扱わない。お年玉を渡す側が、画面に表示された上乗せ額を基準額に足して渡す。
- 金額は「1,000円」の形式 (3 桁区切り + 円) で表示する。

| ○の数 | 当たり枠 | 内訳 |
| --- | --- | --- |
| 0 | 1 | 当たり 1 |
| 1 | 2 | 当たり 2 |
| 2 | 3 | 当たり 3 |
| 3 | 4 | 大当たり 1 + 当たり 3 |
| 4 | 5 | 大当たり 1 + 当たり 4 |
| 5 以上 | 6 | 大当たり 1 + 当たり 5 |

### 2.5 回転の仕様 (F3)
- 「ルーレットを回す」で、盤面が時計回りに 5 回転以上して止まる。所要時間は約 4.2 秒。
- 止まるマスは、押された時点でクライアント側が乱数で決める (10 マス等確率)。
- 指針は止まるマスの中央ではなく、マス幅の ±30% の範囲でずらした位置を指す (演出のため)。
- 2 回目以降は、前回止まった角度から続けて回す。常に前方向にだけ回り、逆戻りしない。
- `prefers-reduced-motion` のときは回転せず、0.6 秒で停止位置に切り替える。
- 回転中は操作できない。停止後に結果 (上乗せ額のみ) を表示する。

## 3. 指標の自動取得 (F4)
- Cloudflare Cron Triggers で定期実行し、外部 API から 6 指標の最新値を取得して ○/× を判定する。
- 判定閾値は設定画面を設けず、システム内の定数として管理する。
- 結果を KV に保存する。
  - 最新: `indicators:latest`
  - 履歴: `indicators:history:{YYYY-MM-DD}`
- 取得に失敗した指標は、前回成功した値を維持する。画面には取得日時を表示して、古い値であることが分かるようにする。
- 判定に誤りがあった場合は、Cron を待たず同じ取得・判定の処理を手動で再実行する (実行方法は未確定。§8)。管理画面は設けない。

保存データ (案):
```jsonc
{
  "fetchedAt": "2027-01-01T00:00:00.000Z",
  "indicators": {
    "cpi": { "on": true, "value": 2.3, "updatedAt": "2027-01-01T00:00:00.000Z" }
    // wage / shunto / mood / stock / bonus も同様
  }
}
```
履歴は `indicators:history:*` に上記と同形式 (+ 当たり枠数) を保存する。

## 4. 履歴の表示 (F5)
- Cron 更新のたびに指標値・○/×・当たり枠数を日付つきで追記し、`/history` に新しい順の縦リストで表示する。
- 保持期間・粒度は未確定 (§8)。

## 5. エラー時の表示 (F6)
- 存在しない URL では 404 のエラー画面を表示する。
- 予期しない例外では汎用のエラー画面を表示する。
- 指標を KV から読めない (値がまったくない) ときは、ルーレットを表示せずエラーを表示する。
- 外部 API の障害で指標が更新できなくても、前回値でルーレットは回せる (§3)。

## 6. 層構成
| 層 | 責務 |
| --- | --- |
| 画面・API のルーティング | URL ごとの描画、API のレスポンス生成。データは下位の層から受け取る |
| ロジック | 当たり枠・上乗せ額の計算、各指標の ○/× 判定。外部に依存しない |
| 外部連携 | 外部 API からの指標取得、KV の読み書き |
| UI | ルーレット、指標の解説ポップアップ |
| 定期実行 | Cron から外部連携とロジックを呼び出し、結果を KV に保存する |

## 7. 非機能要件
- Cloudflare Workers 上で動作する。
- API 鍵はシークレットで管理する。
- スマホ縦画面を基準にレイアウトする。`prefers-reduced-motion` に対応する。

## 8. 未確定事項
| 項目 | 内容 |
| --- | --- |
| 扱う経済指標 | 指標の種類と数 (現状は §2.2 の 6 種類)。増減・差し替えの可能性がある。数が変わる場合、当たり枠数の式 (§2.4) の上限も見直す |
| 判定の方式 | 指標の値そのものではなく、前の期間と比べてどう変化したか (改善/悪化) で ○/× を決める方式にするか。§2.2 の条件は多くが前年比較だが、物価は「前年比+2%超」と基準値を使っている。方式を統一するかも含めて検討する (確証はなく、要検討) |
| 外部 API | 6 指標それぞれの取得元 (e-Stat、日銀、株価データ等) と、取得頻度・利用規約の確認 |
| 判定基準 | §2.2 の条件を API の値でどう計算するか (例: 春闘の賃上げ率の取得元) |
| Cron 頻度 | 指標ごとに公表タイミングが異なるため、日次で足りるか |
| 手動での再実行 | 本番で Cron を待たずに取得・判定を再実行する方法 (ローカルから本番の KV に対して実行する、など) |
| 履歴の保持 | 保持期間と粒度 (日次/月次) |
| 判定の基準年 | お年玉の年ごとに、どの期間の値で判定するか |
